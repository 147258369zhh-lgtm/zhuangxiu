# 装修管理平台

装修公司（B 端）+ 业主/自装人（C 端）通用的装修管理软件。
**当前阶段：自装线先行，形态 = 桌面软件（设计/管理）+ 微信小程序（现场）。**

## 仓库结构

```
├── demo/                 Next.js 交互原型（12 轮迭代）→ 将成为桌面端主体
│   ├── src/app/self      自装工作台：房间点位设计 + BOM 汇总 + CSV 导出
│   ├── src/app/c/[code]  业主端（扫码进工地）
│   ├── src/app/worker    工人端
│   ├── src/lib/data.ts   ★ 领域服务层（40+ 函数）→ 改造成调用真数据层
│   └── src/lib/db.ts     SQLite 假表（14 张）→ 将被 33 张真表替代
├── 开源参考/              11 个调研项目（各自独立 git，不并入本仓）
└── *.md                  规划与路线文档
```

## 怎么跑

```bash
cd demo
npm install          # 首次
npm run dev          # http://localhost:3300/start
```

**演示入口：`/start`**（双端导航 + 演示动线）

| 路由 | 说明 |
|---|---|
| `/start` | 演示导航（先看这个） |
| `/self` | 桌面端自装工作台：点位 / 材料清单 / 预算 / 验收 / 同步 五个 tab |
| `/m` | 小程序端（手机尺寸）：首页 / 清单 / 记账 / 验收 / 照片 |
| `/` | 旧的公司装线原型（仍是旧 SQLite 假表，未接新库） |

校验脚本（不需要起服务）：

```bash
node scripts/verify-schema.mjs      # 组合外键 / 部分唯一索引真的拦得住
node scripts/smoke-all-tables.mjs   # 33 张表逐张插一行，抓 foreign key mismatch
node scripts/check-numbers.mjs      # 从库算 BOM/预算，和页面数字对照
```

数据文件 `demo/.data/self.db`（33 张表，首访自动建表+种子）。删掉它重启即恢复演示数据。

## 关键决策

| 项 | 结论 |
|---|---|
| 产品形态 | 桌面软件（Electron + Next.js）+ 微信小程序（uni-app），自装线先行 |
| 数据真相 | 桌面本地 SQLite；云端（微信云开发）只做快照与事件转接 |
| 同步 | 小程序仅 append 事件，编辑权只在桌面 → 冲突面≈0 |
| 桌面表数量 | 33 张（117 张里砍掉多方参与相关 84 张） |
| 变现 | 小程序免费获客，桌面 ¥29.9 买断 + 离线 ECDSA 授权 |
| 不做 | NestJS 拆分、Prisma、Tauri、双向行级同步 |
